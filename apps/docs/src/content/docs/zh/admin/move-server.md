## 整个实例：通过备份

这会迁移一切（每个账号、位置、文件与设置），流程与从丢失的服务器中恢复相同：

1. 在旧服务器上做一次备份并等它完成，然后打印[恢复套件](/zh/admin/recovery-kit/)。
2. 在新服务器上，[安装 Kept](/zh/install/compose/)，把套件中的密钥放入 `.env`，并使用相同的备份目标，但**先不要启动 Kept**。
3. [恢复](/zh/admin/restore/#after-losing-the-server)最新备份到新的空数据库。
4. 把旧地址指向新服务器（DNS 或反向代理），保持 `KEPT_PUBLIC_URL` 不变，然后启动 Kept。标签与二维码继续可用，因为地址没有变。
5. 新服务器检查无误后停止旧服务器；在新服务器完成一次正常备份并通过[恢复演练](/zh/admin/restore/#the-monthly-drill)之前，保留其磁盘。

如果地址确实变了，已打印的标签仍带着旧地址：把旧主机名也指向新服务器，并把它列入实例的曾用主机名；Kept 会把旧名称下的访问重定向到新地址上的同一页面。

## 一次一个位置：通过导出

所有者导出一个位置（含其文件，可选地在口令下导出机密值）；在新服务器上导入为一个新位置。这会迁移一个家庭而不带动实例其余部分，也可在运行不同版本的两个实例之间进行，只要新版本不比旧版本更旧（较旧的 Kept 可能拒绝来自较新版本的导出）。

1. 在旧服务器上，进入 **Settings → Export**，导出该位置。选择是否包含机密值；若包含，请设置口令。导出仅通过 HTTPS 生成，并保持可下载 7 天。
2. 在新服务器上登录，打开 **Settings → Import**，选择 Kept 导出文件（ZIP）。Kept 会先检查，并在写入任何内容之前显示将添加什么；输入口令以恢复机密值。
3. 导入会创建一个**新位置**，包含物品、位置、文件、状况报告、移动记录及其历史。已打印的标签继续可用：标签的短代码在新服务器上空闲时会被保留，不空闲时会重新签发；此时扫描旧标签仍会打开该物品。
4. 邀请共享该位置的人；导入会列出他们，但不会自动发出邀请。
