**房间**是一种快速填充 Kept 的拍摄模式：对房间、柜子或架子最多拍五张照片，AI 会列出看到的每件物品。Kept 会在两张照片中看到的同一物品上合并，跳过 Kept 已有的，其余放入收件箱，成为已在该房间中的草稿，每项附带从照片裁出的自己的图片。

## 开始前

房间模式用 AI 读取照片，因此需要与其他 AI 拍摄相同的条件：

- 该位置开启了 **AI 拍摄**（所有者或管理员在**位置设置 → 跟踪内容**中开启），并配置了能读照片的 AI 提供商（[AI 提供商](/zh/users/ai-providers/)）。
- 你能在该位置编辑物品：成员、管理员与所有者。查看者看不到该模式。

房间无法运行时，模式会说明原因而不是隐藏：该位置关闭了 AI 拍摄、未配置能读照片的提供商，或 AI 预算暂时用尽。

## 拍摄照片

1. 打开**拍摄**，然后在模式条上选择**房间**。从位置页面，**从照片填充**会针对该位置打开；在[位置地图](/zh/users/location-map/)上，房间卡片有**拍摄此房间**。
2. 确认照片去向：顶部的位置芯片。房间拍摄会进入房间、点位或箱子，绝不进入未放置区域。
3. 拍 1 到 5 张照片，或用**图库**选择。站在门口，每面墙拍一张。每张照片都在托盘中等待，可在其中移除。
4. **发送**。离线时照片在手机上等待，恢复联网后发出，与其他拍摄相同。

照片中的 Kept 标签会在发送前在手机上读取。标签被读到的物品是确定已知的，无论它在位置中的何处。

## 审阅房间

收件箱在该批拍摄的开头显示一张**房间**卡片，其下是生成的草稿：

- **新物品：**每件都是房间中的草稿，附带自己的照片，并在照片显示处填好名称、品牌、型号、颜色与类型。像任何草稿一样接受、编辑或丢弃，或对整批**接受名称**。看起来像你已有物品的草稿会标为可能重复。
- **能放东西的家具**（架子、书柜、柜子、衣柜、抽屉柜）：**添加为位置**会把每件变成房间内的位置，以便物品放入。其他家具（沙发、床、桌子）是与普通物品一样的草稿。
- **Kept 已有：**照片中显示、而房间已有的物品，依据相同标签、相同品牌与型号，或相同名称。勾选它们并**标记已见**。标签被读到的物品默认已勾选。
- 每张照片会说明它贡献了什么。“无法读取第 3 张照片”表示该张失败，其余仍有效；“这张照片内容更多；请拍得更近一些”表示它显示的超过一张照片能列出的上限（60 件）。

人员、宠物与房间本身（墙、地板、窗、门、固定装置）从不列出，也从不会裁出人物照片。

**完成**关闭卡片。**丢弃**放弃照片。当没有任何照片能被读取时，**重试**会再次读取。

### 在地图上

当房间绘制在[位置地图](/zh/users/location-map/)上时，每件被接受的物品会按类型与名称猜测的形状放在房间地面上的空位。下次你**整理**时，地图会列出 Kept 摆放了什么，以便你把每件移到实际位置。Kept 摆放物品从不会打断同时正在整理地图的人。

## 费用

每张照片是一次 AI 读取；超过一张照片的拍摄还会增加一次简短的纯文本调用，用于合并照片的共同点。发送前，托盘会显示上限，例如“约 3 张照片，最多约 31,000 tokens，Groq”：每张照片对应照片本身、指令，以及 Kept 允许的最长回答；回答越短费用越低。会先思考再回答的模型会另计思考费用。

房间读取计入与其他照片读取相同的预算与限额。达到限额时，卡片显示“等待 AI 预算”，AI 恢复后会读取照片。每次调用在 **AI 用量**中显示为**房间照片**或**房间照片已合并**。

## 隐私

- 提供商收到的内容与任何拍摄相同：每张照片的副本（已去除位置与相机数据）以及固定指令。
- **关闭房间卡片时（完成或丢弃）会删除完整房间照片。** 每个草稿只保留自己的裁切图片。
- **房间卡片打开期间，其照片仅对审阅者可见：**该位置的所有者、管理员与成员。查看者在房间或箱子页面、搜索或其手机上都看不到；只读 API 令牌、只读 MCP 连接或分享链接也看不到。审阅期间，房间照片绝不会成为箱子的封面照片。
- 若要保留完整照片，所有者或管理员在**位置设置 → 常规**中开启**审阅后保留房间照片**。**完成**之后，它们会作为普通照片留在房间页面上，所有能查看该位置的人都能看到。

## 在试用 Kept 中

[试用 Kept](/zh/try/kept/)没有摄像头，也不运行 AI：房间模式提供**使用示例房间照片**（一间示意房间），每张房间照片都给出相同的示例结果，因此无需提供商也能看到房间卡片、草稿与家具。托盘会显示“此演示不运行 AI”，真实安装中该处会显示费用。
